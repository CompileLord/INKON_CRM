# WP-12 — SMTP certificate verification and socket timeout

Date: 2026-10-15 UTC. Branch: `remediation/wp-12-smtp-tls`. Implementation: `/root/wp02_review`; independent review/audit: `/root`. Backend-only assignment; frontend checks belong to the user's separate agent. No deployment, external mail, operational data changes, push or PR.

## Change and review

SMTP STARTTLS now uses `ssl.create_default_context()` before AUTH, retains the post-TLS EHLO and `asyncio.to_thread`, and applies a 10-second timeout to socket operations. Certificate, TLS, authentication and transport errors expose sanitized messages without server responses, credentials or message bodies. Private trust bundles can be supplied through the standard SSL trust configuration; verification is never disabled in the implementation.

Review covered correctness, readability, architecture, security and performance. Changes are confined to the existing email service, the authorized regression module and this WP's administrative evidence. The original async method is captured before the suite's email mock, so the probes execute real SMTP. Loopback SMTP fixtures and short-lived certificates exercise untrusted CA rejection, trusted wrong-host rejection, deliberately trusted correct-host delivery, ordered TLS/EHLO/AUTH/data, and a stalled greeting. Rejected peers receive neither authentication nor message data.

## Comparable timeout and thread measurements

Same Conda runner, synthetic local SMTP server and command in both versions: `PYTHONPATH=/scratch/backend python /scratch/wp12/wp12_benchmark.py`, with `WP12_VERSION=before` or `after`. The before file is the committed pre-fix service; the after file is this change. The temporary helper was reviewed. Each concurrency group has one single-request warmup and three trials, each using a fresh event loop/server. Server delays its EHLO reply and self-releases after 1.3 seconds, bounding baseline execution. The fixed version uses a **test override of 0.35 seconds**; production uses 10 seconds. These are controlled failure durations, not successful mail latency or production throughput.

|---|---|---|---|---|
| 1 | 1.3066, 1.3035, 1.3062 | 1.3054 / 0.0017 | 0.3572, 0.3552, 0.3570 | 0.3565 / 0.0011 |

All trials failed as intended against the stalled synthetic server. In both versions, peak in-flight SMTP calls / executor threads were 1/1 at concurrency 1 and 10/10 at concurrency 10. Zero calls remained active at completion. The executor retained 1 or 10 idle threads until event-loop shutdown; this is not a thread-count reduction. Durations exclude waiting for fixture server cleanup after completed calls. Logs: `wp12-performance-before.log` and `wp12-performance-after.log` in the temporary directory above. Measurements were serialized with other remediation checks paused.

A socket timeout bounds individual blocking operations, not total message duration when a peer keeps making progress. Mail can still occupy request transactions; WP-18 owns removing it from that transaction path. Cloud SMTP configuration and live delivery were not exercised.
