## Fixture behavior

Before any application import, TestTargetConfiguration requires explicit TEST_DATABASE_URL and TEST_REDIS_URL, TESTING=true and ENVIRONMENT=testing. It accepts only the declared loopback PostgreSQL target on port 5432 named imkon_test_db and loopback Redis port 6379 database 15. Missing, shared or ordinary application targets fail closed. Query and fragment components are rejected because drivers can interpret them as target overrides. No test Redis URL is derived from application fallback settings. Application database/Redis settings are replaced with the validated targets before imports.

Request and worker factories are explicitly redirected to the same TestingSessionLocal. Redis application commands receive a unique process/run namespace. Client and pipeline operations expose only the supported typed commands; global and unsupported commands are absent. Pipeline deletion namespaces every key. Autouse Redis cleanup runs before and in finally after every test, independently of db_session/client fixture use. It scans/deletes only the run-owned prefix; unrestricted FLUSHDB is removed. The raw dedicated Redis connection is exposed solely as a test fixture for sentinel probes. This is a fixture safety protocol, not a sandbox for hostile test code.

The new requirements intentionally make an unconfigured developer test invocation fail before destructive schema setup. A disposable environment must explicitly supply these settings before imports and still provision isolated storage. Worktree/runner settings used here are temporary and are not committed.
