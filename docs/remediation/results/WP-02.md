## Exact reproduction selectors and observed defects

- `app/tests/regression/critical_reproductions.py::test_refresh_cross_user_same_second`: freezes token minting time, logs in administrator and student, then refreshes the student's credential through HTTP. Distinct-credential, student-subject, and student-role assertions are all false: the credential collides and the student receives administrator access. Token strings are not placed in assertion messages.
- `app/tests/regression/critical_reproductions.py::test_private_document_download`: uploads synthetic private bytes as administrator, follows the returned path anonymously and as a separately committed student. Both callers receive status 200 and the original bytes. Final assertions require client-error denial and withholding the private bytes independently for each caller. Success, redirects, and server errors do not pass.
- `app/tests/regression/critical_reproductions.py::test_concurrent_allocation`: two distinct PostgreSQL backend PIDs rendezvous at an asyncio barrier before the service reads, each tries to allocate 75.00 against the same 100.00 credit and charge, and commits independently. A fresh verification session observes charge allocation 150.00. Both the charge cap and payment cap have explicit assertions; nonzero totals prevent a no-op from passing.
- `app/tests/regression/critical_reproductions.py::test_concurrent_refund`: two independent committed writers rendezvous before service reads and each refunds 75.00 from the same 100.00 payment. The fresh-session SQL aggregate reports refunds 150.00. Nonzero and maximum-total assertions test the financial invariant.

The ledger tests use actual PostgreSQL sessions, SQL aggregate verification, Decimal money, no timing sleeps, and a 15-second timeout that fails rather than skips a stuck race. They allow an expected 400 rejection after rollback when a valid serialization fix prevents the second write. The barrier is outside service reads and locks, so a real locking fix can serialize without a test-created lock/barrier deadlock. Repetition reproduced all four baseline failures; this is not an exhaustive scheduler exploration or a performance benchmark.
