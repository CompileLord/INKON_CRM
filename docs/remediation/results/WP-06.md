## Backend behavior

AccessTokenPrincipal.from_token owns signed-token parsing. It requires canonical ASCII decimal subjects in the positive PostgreSQL User Integer domain; access purpose; supported scope; integer exp/iat; a valid expiry, nonfuture issuance, and lifetime within the configured access-token limit. Library TypeError/OverflowError for malformed time claims become JWTError and then the existing generic 401, rather than escaping as server errors. Newly issued access credentials declare their purpose; legacy credentials lacking type remain compatible when their other claims are valid. No current caller uses a custom expiry beyond the configured bound.

Ordinary authentication rejects both setup-only credentials and accounts whose database record still requires setup. The explicit setup dependency permits a setup-scoped credential only while setup is pending, and is used by set-password alone. After password setup clears the database flag, the original scoped JWT stays restricted. Login, refresh and password-reset issuance retain setup scope when required; the successful setup flow issues ordinary access credentials. Accepted refresh identity and atomic single-use behavior are preserved.
