Staff access remains superadmin or assigned mentor. Student reads remain restricted to the enrolled student's own row and use Group 06 routes. A 403 after a permission/archive change must preserve unacknowledged work for review while blocking further writes; it must not be shown as Saved or a generic empty roster.

Period selection order: valid `period` query parameter belonging to this course; otherwise the period whose start ≤ course-calendar today ≤ end; otherwise the latest already-started period; if every period is future, the earliest upcoming period. A missing period list produces its own empty state, with no fabricated editor.

Lesson selection within that period: valid explicit `lesson` date; otherwise today's scheduled lesson; otherwise latest scheduled lesson on/before today; otherwise first scheduled lesson. Use only returned `lesson_dates`. Previous/next stop and disable at the period boundary; they never silently select another period. Resolve the established course calendar/timezone before date-only comparisons; do not derive today by UTC slicing without that contract.

Invalid period/date query values show a short translated notice, select the documented fallback and normalize the URL without adding history entries. Query changes and browser Back/Forward must update visible context; one-time `useState(defaultExpanded)` is insufficient. Preserve supported `period`, `lesson`, `view` and gradebook mode across navigation, along with roster search, scroll anchor and focused student/control in route state. Do not put draft values or personal comments in URLs. Use replacement history for routine lesson/tab/mode changes; route entry/exit remains a meaningful Back step. ## Persistence ownership, navigation and conflicts

Implement persistence repairs before mounting separate responsive editors. Own one canonical journal queue above Grid/Lesson/Summary/Progress, keyed by actual journal ID. Mode switches, student breakdown and resize do not recreate it. Never mount separate desktop/mobile autosave hooks for the same journal. Preserve the existing debounce/batch intent (700ms debounce, 3000ms maximum latency and bounded retry schedule) while repairing unsafe lifecycle behavior; versions, partial-batch contract and server concurrency validation remain intact.

The owner keeps confirmed server state, latest local draft, submitted in-flight snapshot and outcome separately for entries and paired summaries. An older acknowledgement may update the known server version but may not erase a newer local value. A failed in-flight request may not replace a newer queued draft with its stale snapshot. Pending state includes queued and in-flight entries, queued and in-flight summaries and unresolved conflicts.

Expose a typed drain result: fully acknowledged, failed, or conflict/unavailable. Drain resolves successfully only when all queued/in-flight work and chained edits for that journal have settled successfully. The current early-returning/catching `flush()` is not this guarantee; simply awaiting it is insufficient. Period/course/route changes, explicit profile navigation, bottom navigation and browser Back use this boundary. Freeze context switching while draining, without disabling unrelated read access. Capture edits arriving during a drain so it cannot report success early. No old-period draft may be sent to the newly selected journal ID.

On failed/conflicted drain, retain old context and local drafts; show Retry or Review, Stay, and an explicit Discard unsaved changes action. Discard applies only to unsettled local work and restores confirmed state; it does not undo acknowledged writes. If an in-flight response is still uncertain, do not pretend cancellation/discard reverses the server request: settle/refetch that outcome before leaving under a success claim. Browser unload/visibility flushing is best-effort with the unsaved warning; no guaranteed save after unmount, request cancellation or network loss. No cross-session/offline recovery claim.

The reserved status area uses priority **Conflict → Failed → Saving → Unsaved → Saved**, covering entries and summaries. It remains present in Progress too while work is unresolved. Conflict/Failed includes an actionable Review/Retry; Saved appears only when no unsettled work remains. One polite live region summarizes changes without announcing every keypress. Per-cell markers use shape/icon plus accessible status; never color or opacity alone. No new success toast stream.

Conflict review shows student, lesson/summary context and complete labeled Your value/Server value fields, including readable comments. Preserve the sent local snapshot and latest draft before applying any server response to cache. Keep mine submits the chosen latest local draft with the returned current version; Use server updates editor and server-derived summary consistently. A newer local edit arriving during a conflict is not silently rebased into overwriting someone else's value. Keep both sides until explicit resolution. A repeated concurrent edit can conflict again. Disable duplicate resolution while pending while leaving unrelated rows usable.

A conflict with `current: null` shows Entry unavailable and Refetch; Keep mine is disabled when no current version exists. A summary 409 without a full snapshot refetches authorized current summary data before offering a meaningful comparison. If recalculated summary data is unavailable after resolution, mark it refreshing/unavailable and retry rather than inventing a total. Preserve backend optimistic locking, rollback and 409 behavior.

Apply entry-batch successes and each summary's outcome independently. Do not wait for all summary promises before acknowledging an already-applied entry batch; one rejected summary must not resend or revert successful siblings. Retain unresolved local data, retry only unsettled operations and invalidate/refetch derived Progress/metrics after acknowledged writes without disrupting focus. Progress failures never block Gradebook or discard drafts.

## Motion, implementation boundaries and order

Score-picker open/close, grading keys, focus movement, lesson/period/tab changes and data refresh are immediate. Standard pointer feedback uses 150ms ease-out and `motion-safe:active:scale-[0.96]` on the control only; disabled controls stay still. Occasional comments/settings can reuse shared opacity/scale .96→1 at 200ms ease-out with `motion-safe:` and matching close, without delaying focus or writes. If comment use becomes frequent, keep it immediate as well. Reduced motion has static immediate surfaces; no global motion override or new motion library. Remove row fades, transition-all, animated chart drawing and save flashes as touched. No global suppression of native page scroll or swipe-only actions.

Reuse React Router, React Query, Zustand, existing forms, native tables/SVG and the shared accessible dialog/popover primitive selected in Group 01. No spreadsheet, chart, gesture or animation dependency is required. No app-wide dependency churn for this group.
