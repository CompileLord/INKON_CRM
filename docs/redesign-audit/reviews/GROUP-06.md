# Group 06 independent review — learning, settings and personal notifications

Status: recommendation only, awaiting user selection. This review changes no baseline plan, application source, token, API, capture or task status. No implementation verification or commit is claimed.

The baseline correctly prioritizes truthful data states, readable phone forms and personal inbox scope. The strongest improvement is to reduce the number of competing summaries and actions. A learner should quickly find a course, open a period and understand the result. Settings should make persistence boundaries visible. Notifications should communicate an event without exposing a delivery console.

## Desired structure and style

**My courses:** one 24px phone / 28px desktop heading; Active/Archive with counts; compact course identities containing title, teacher, backend status and a small labeled personal result. Use a 48–64px thumbnail only as identification. Remove the duplicate total count next to the heading when tab counts already supply it. No search for a single captured course. Empty archive has brief explanation and one return-to-active action, without a hero illustration or celebratory tone.

**Course detail:** compact identity; configured weekly schedule context; periods as the main navigable section; quiet own-result/attendance summary; optional comparison/trend; description. On desktop use a main reading column and a roughly 280–320px schedule/description column; do not spread a sparse page across every available pixel. On phone use 16px gutters, 16px panel padding and divided period rows. Avoid an outlined box for every metric and teacher label.

**Own period:** unboxed back/title/date context; one result region; one lessons region. Lesson rows show date, attendance and labeled homework result with room for a comment disclosure on a separate line. Preserve content selection and no-hover access. Keep the existing chronological order unless user research establishes a need to reverse it; do not add date filters or lesson-navigation controls merely to populate space.

**Account:** bounded approximately 640px reading/form width. One-column fields on phone with visible labels and 48px-high, 16px inputs. Email is selectable wrapped read-only text rather than a visually disabled input. Profile Save belongs immediately after profile fields, before immediate appearance choices. Avatar status stays local. Admin has a clear section selector; at 320px use a labeled selector or a contained horizontally scrollable tab strip with keyboard support, rather than compressing three translated labels into the document width. Nonadmins get no lone tab.

**Notifications:** compact heading and quiet Refresh action; a bounded event list with event title, date and read affordance. Unread rows use an accessible text/state cue and modest emphasis, not a full colored card. True empty state removes both technical columns and filters: short heading, one sentence that events will appear for this account, and refresh in the normal header. Do not claim “all caught up” if there have never been events. Date-only and delivery timestamps retain their distinct meanings.

Use KITOB navy/blue for navigation, links and focus; white/cool light surfaces and readable blue-gray dark surfaces from the proposed semantic tokens. Orange is a small supporting accent, not the default color for every grade, active label and button in dark mode. The supplied emblem belongs to the shared shell, not repeated inside course, settings and empty-state cards. Preserve logo artwork and give its dark-surface placement to Group 01; no asset transformation is proposed here. Use token foregrounds rather than literal white on dark-theme primary buttons. All changing values use tabular numerals; any future monetary content remains decimal strings.

## Motion and libraries

No additional Group 06 motion pattern is justified. Reuse shared press feedback only: pointer press scale 1→0.96, transform 150ms ease-out, motion-safe; immediate disabled/focus behavior. Frequency is tens of interactions, purpose is feedback, budget is 150ms, and readable content does not move. An actual occasional popover can use the established opacity/scale surface recipe at 200ms; inline comment and score disclosures need no height animation.

Rejected: score counting/track filling (functional data gate), period-row stagger (frequent navigation gate), theme-wide crossfade (reading stability gate), celebratory empty inbox animation (no useful purpose), swipe-to-read or swipe-between-settings (hidden gesture with unnecessary implementation cost). `frontend/package.json` provides existing router/query/forms/Zod/Zustand infrastructure. Retain it, the current SVG and shared primitives. No Motion, NumberFlow, new chart, toast, gesture or state package is needed for this group.

## Selection and verification boundaries

Select M1, M2, M5–M7 and the removal table first; they materially simplify the interface without adding product scope. Treat chart accuracy and rank semantics as explicit correctness work. A genuine webhook-health endpoint, message-body contract, global inbox search and cross-period grading policy are separate capabilities and should not block shipping the truthful smaller UI.

Implementation evidence should include an own-row privacy case with another student's nonempty private comment, cross-user mark-read denial, equal-score ranking decisions, a valid zero and above-100 score, missed past entry versus future lesson, profile clear/discard/refetch behavior, independent avatar/save failure, and failed/sent/read notification combinations including internal score markers. Verify filter-free true empty separately from paginated populated data. Reuse the baseline's mandated full suites, parity, typecheck and schema regeneration gates.

The new geometry needs both themes at 320/390/768/1024/1440, long Russian/Tajik labels, long email, keyboard focus and reduced motion. Physical iOS/Android keyboard, safe area, browser chrome and touch checks remain unperformed. Populated inbox/archive, API failure and mutation states require authorized fixtures during implementation; this review invents none and makes no claim that they were captured.
